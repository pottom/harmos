You don't browse a vault.
You raid it.

Ninety-five percent of sessions are one sentence: get me the X password, into the clipboard, go away. So the real question isn't “how do I show a tree” — it's “how few keystrokes from launch to copied.” Four directions, same data, same job. One is built to win; the others earn their place.

● teal = fresh cache ● rust = stale / expiring amber = a secret & the act of copying it steel = everything else
Concept — Palette

Type first, ask questions never.One box. Launch lands you in the search. Enter copies. That's the whole app for most sessions.

When it wins

The daily driver. Launch → three keystrokes → copied → gone. No panes to orient in, no tree to expand. Source + freshness ride on every row so a wrong-source copy is impossible to miss. This is Raycast/Spotlight muscle memory, applied to secrets.

The catch

Weak at exploring — “what's even in client-a?” means searching blind. Pair it with a one-key ⇥ peek (detail) and a tree drop-down for the rare browse, and the gap closes.

Concept — Cascade

Walk it like a shelf.Miller columns — source ▸ folder ▸ entry ▸ detail. Provenance is the path you walked. (Charm theme.)

← → columns ↑ ↓ rows ↵ copy / search space peek

When it wins

Exploration and trust. When you don't know the exact name, you walk the shelves — and the columns you traversed are the provenance, structurally. Great for auditing “what does this source actually hold,” and it maps cleanly onto the two-producers model.

The catch

Slower for the 95% case — more keystrokes than a search box. And it leans on width; three columns want ≥100 cols. Charm's purple is handsome here but competes with the amber-for-secrets rule.

When it wins

The security story, made visible. Cache age and expiry are the most important facts when you're offline — this puts them first, and turns “is my client-a cache stale?” into a glance. It's the screen you'd show the security team.

The catch

It's a home, not the fast path — an extra hop before the search that most sessions actually want. Best as the landing screen that a keystroke collapses into Palette, not the main event.

When it wins

Power users who live in it. Everything about the selected entry — username, url, TOTP, attachments, cache age — is visible without a second screen. One-key copy for each field. This is the k9s/lazygit density that pros love.

The catch

Needs width (≥100 cols) and is busier — more to take in than the calm Palette. It's the “I'm working in here for a while” mode, less the “grab and go.”

My read as design lead

Design for the sentence, not the tree. The job is launch → copied → gone, so the default should be Palette — the fewest keystrokes, the calmest surface, provenance on every row. Then don't make the others separate apps — fold them in as gestures on the one surface:

DefaultPalette — the search-first fast path. Launch lands here, always.
⇥ peek → SplitTab expands the selected result into the rich detail. Same screen, more depth.
↓ from empty → ConsoleAn empty query reveals the vital-signs home: sources, staleness, expiring.
/ tree → CascadeA modifier drops into column-walking for the rare “what's in here?” browse.

One coherent tool with a fast heart and three depths, not four screens. Amber stays reserved for secrets in every mode, so a wrong-source copy always jumps out. Tell me which direction sings to you — or which pieces to splice — and I'll build that one as the working prototype next.
